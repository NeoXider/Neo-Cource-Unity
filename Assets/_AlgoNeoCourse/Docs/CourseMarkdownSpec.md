# CourseMarkdownSpec

Актуальная спецификация уроков для `AlgoNeoCourse`.

## 1. Структура курса

Каждый курс описывается отдельным JSON-файлом:

- `course1.json`
- `course2.json`
- любой другой `courseN.json` для режима `Custom`

Минимальная структура:

```json
{
  "title": "Название курса",
  "description": "Короткое описание",
  "lessons": [
    { "id": "l2m2y1", "title": "Основы синтаксиса C#", "file": "lessons2/m2/y1.md" }
  ]
}
```

Правила:

- `id` должен быть уникален в рамках курса;
- `file` хранит путь к `.md` файлу;
- путь задаётся относительно источника курса.

## 2. Один урок = один `.md`

Каждый урок — это отдельный Markdown-файл, указанный в `file`.

Пример:

```json
{ "id": "l2m2y3", "title": "Операторы", "file": "lessons2/m2/y3.md" }
```

## 3. Слайды

Слайды разделяются строкой `---`.

```md
# Введение

Короткий контекст.

---

## Теория

Объяснение темы.
```

Правила:

- используйте `#` для титульного слайда;
- используйте `##` для обычных слайдов;
- держите один слайд = одна мысль.

## 4. Медиа

Поддерживаются:

- относительные пути от текущего `.md`;
- `Assets/...`;
- `Packages/...`;
- поиск по имени файла;
- внешние `http://` и `https://` URL.

Примеры:

```md
![](images/example.png)
![](videos/demo.mp4)
![](https://example.com/reference.jpg)
```

GIF:

- как анимация GIF не проигрывается;
- для анимации используйте `.mp4`.

## 5. Таблицы

Таблицы пишутся в формате pipe table и показываются сеткой (с версии 1.8.0):

```md
| Тип     | Пример  | Байт |
| :------ | :-----: | ---: |
| `int`   | `42`    |    4 |
| `float` | `3.5f`  |    4 |
```

Правила:

- нужны строка-шапка и строка-разделитель под ней (`| --- | --- |`); перед таблицей — пустая строка;
- строка-разделитель задаёт выравнивание колонки: `:---` влево, `:---:` по центру, `---:` вправо;
- пишите разделитель с символами `|`: строка из одних `---` — это граница слайда;
- в ячейках работают **жирный**, *курсив*, `код`, ссылки и картинки; сам символ `|` пишется как `\|`;
- текст с `|` без строки-разделителя остаётся обычным абзацем;
- таблица занимает ширину слайда, длинный текст переносится внутри своей колонки — держите таблицы
  небольшими (до 4–5 колонок), иначе на узком окне колонки станут тесными;
- объединения ячеек, многострочные ячейки и таблицы внутри списков (там таблица выводится строками
  текста «ячейка | ячейка») не поддерживаются.

## 6. Квизы

Квизы оформляются через fenced-блок `quiz`.

```quiz
id: l2m2y3-q1
kind: single
text: Какой оператор выполняет проверку условия?
answers:
  - text: if
    correct: true
  - text: for
  - text: while
```

Поддерживаемые типы:

- `single`
- `multiple`
- `truefalse`

Правила:

- у каждого квиза должен быть уникальный `id`;
- один вопрос лучше размещать на одном слайде;
- пояснение к ответу лучше выносить на следующий слайд.

Прогресс квизов сохраняется локально автоматически.

Настройки квизов:

```text
Tools -> AlgoNeoCourse -> Settings -> Open Quiz Settings
```

Ключевые параметры:

- `maxAttemptsPerQuestion`
- `randomizeAnswersOnCourseOpen`
- `guardSlideNavigation`
- `stateJsonFolder`

## 7. Автопроверки

Автопроверки оформляются через fenced-блок `check`.

````md
```check
rules:
  - object_exists: "Player"
  - component_exists: { object: "Player", type: "Rigidbody" }
  - filename: "PlayerController.cs"
  - contains: "public class PlayerController"
```
````

### Правила и параметры

Полный список правил:

| Правило | Что проверяет |
| --- | --- |
| `object_exists: "Player"` | Объект с таким именем или путём в загруженных сценах, включая выключенные объекты. |
| `component_exists` | Компонент на указанном `object` или `prefab`; без обоих — на любом объекте загруженных сцен. Нужен `type`; короткая запись: `component_exists: "Rigidbody"`. |
| `field` | Значение поля / свойства компонента: обязательны `object` или `prefab`, `type`, `name` и одно из `equals` / `count`. |
| `scene_name: "Main"` | Загруженная сцена; допустим путь и суффикс `.unity`, регистр не важен. |
| `filename: "PlayerController.cs"` | Наличие файла в проекте. |
| `contains: "void Update()"` | Точное вхождение строки с учётом регистра в файл ближайшего `filename` выше. Для старых уроков `contains` перед первым `filename` использует первый файл блока. Без `filename` правило некорректно. |

Это ограниченный формат, похожий на YAML, а не полный YAML. `rules:` — заголовок списка;
необязательная строка `type: scene`, `type: script` или `type: combined` вне правила игнорируется.
Пишите правила с `-`, а параметры — без дефиса непосредственно под правилом.
Пустые строки и строки-комментарии `# ...` пропускаются. Значения можно заключать в одинарные
или двойные кавычки; числа с дробной частью пишутся через точку. Цвета с `#` заключайте в кавычки.

Параметры:

- `optional` подходит любому правилу; по умолчанию `false` — обязательная проверка;
- `object`, `prefab`, `type` подходят только `component_exists` и `field`;
- `name`, `equals`, `count`, `tolerance` подходят только `field`;
- строка `key: value` без дефиса присоединяется к предыдущему правилу только при подходящем,
  ещё не использованном ключе; иначе разбор параметров заканчивается и строка разбирается
  как отдельное правило — так сохраняется совместимость со старыми уроками;
- параметры в `{ ... }` поддерживаются только у `component_exists` и `field`.
  Неизвестный или повторный ключ в такой записи — ошибка. Не дублируйте параметры между
  `{ ... }` и следующими строками; `object` и `prefab`, а также `equals` и `count` взаимоисключающие.

### Дополнительные проверки и результат

`optional: true` делает правило дополнительным. Без параметра или при `optional: false`
правило остаётся обязательным, поэтому старые уроки сохраняют прежний зачёт.
Допустимы также `yes` / `no` и `да` / `нет` без учёта регистра; для единообразия используйте `true` / `false`.

````md
```check
rules:
  - object_exists: "Player"
  - filename: "PlayerController.cs"
  - contains: "Debug.Log"
    optional: true
  - field: { object: "Main Camera", type: "Camera", name: "orthographicSize", equals: 5, optional: true }
```
````

Здесь наличие `Player` и файла обязательно; строка в скрипте и размер камеры — рекомендации.
Делайте дополнительными значения, которые зависят от вкуса автора или ученика (размер камеры,
цвет, декоративные настройки). То, без чего игра ломается, оставляйте обязательным.

Кнопка «Проверить» появляется автоматически в карточке «Практика · что проверит Unity».
До проверки у строк знак `○`, статус «не проверено». Дополнительные строки помечены «дополнительно».
После проверки ученик видит:

- **Не засчитано:** обязательный пункт не выполнен либо правило содержит ошибку разбора.
  У проблемной строки красный `✕` и подсказка; статус «готово N из M» (обязательные пункты)
  или «есть ошибки», красная кнопка «Проверить ещё раз», карточка коротко вздрагивает.
- **Засчитано с замечаниями:** все обязательные пункты выполнены, дополнительные — не все.
  У невыполненного дополнительного пункта янтарный `!` и подсказка; статус
  «засчитано · 1 замечание» или «засчитано · замечаний: N», кнопка «Проверить ещё раз».
  После восстановления сохранённого результата статус — «засчитано · есть замечания».
- **Идеально:** выполнены все пункты. Строки отмечены `✓`, статус «идеально · N/N»,
  кнопка «Проверено», по карточке проходит короткий блик. При восстановлении — «идеально» без блика.

Ошибка разбора (например, `field` без `name`, неизвестный inline-параметр или неверное
значение `optional`) проваливает задание даже при `optional: true`. Ошибки, обнаруживаемые
только при выполнении (например, нет компонента или не удалось прочитать свойство),
у дополнительного правила дают замечание.

В отчёте консоли / диалога дополнительные правила отмечены `[дополнительно]`, их невыполнение —
«ЗАМЕЧАНИЕ». Итог разделяет группы: `Итого: a/b, дополнительно: c/d — засчитано, есть замечания`
либо `— идеально`. `a/b` — обязательные пункты, `c/d` — дополнительные. Без дополнительных
пунктов выводится только `Итого: a/b`, без суффикса «идеально».

Результат сохраняется локально для каждой проверки: `LessonQuizState.checkIdToPassed`
хранит зачёт, `checkIdToRemarks` — наличие замечаний. Старые сохранения читаются:
пройденная проверка без записи о замечаниях считается идеальной.

### Объект сцены или префаб

`component_exists` и `field` принимают `object` (объект сцены) или `prefab`
(ассет, экземпляр на сцене не нужен); одновременно указывать их нельзя.
У `field` источник обязателен; `component_exists` без источника ищет компонент на всей сцене.
Тип ищется по имени C# компонента / скрипта; компонент читается на самом указанном объекте.

Префаб ищется по имени файла, без расширения или с `.prefab`. Сначала предпочтительно
точное совпадение регистра имени, затем совпадение без учёта регистра. При одинаковом
совпадении приоритет у папки `_source` (в том числе `Assets/_source`), затем у путей
без сегмента `Demo`, затем у остальных. При равном приоритете не полагайтесь на выбор между дубликатами.
`EnemyShip/ShootPoint` обозначает дочерний объект `ShootPoint` префаба `EnemyShip`;
допустим и более глубокий путь. Это имя префаба и путь внутри него, а не полный путь ассета.

````md
```check
rules:
  - component_exists: { prefab: "EnemyShip/ShootPoint", type: "Transform" }
  - field:
      prefab: "EnemyShip/ShootPoint"
      type: "Transform"
      name: "localPosition"
      equals: "0, 1"
      tolerance: 0.05
      optional: true
```
````

### Поля, свойства и сравнения `field`

`name` — имя члена C#, а не подпись в Inspector. Читаются публичные поля и доступные
для чтения публичные свойства без индексаторов, а также непубличные поля с `[SerializeField]`,
включая унаследованные. Для публичных членов есть поиск без учёта регистра, для непубличных
пишите точное имя. Точки задают путь по вложенным членам: например, `main.duration`.

Частые соответствия:

| Подпись в Inspector | `type` | `name` |
| --- | --- | --- |
| Size | `Camera` | `orthographicSize` |
| Order in Layer | `SpriteRenderer` | `sortingOrder` |
| Position дочернего объекта | `Transform` | `localPosition` (относительно родителя) |
| Is Trigger | `BoxCollider2D` (или нужный Collider) | `isTrigger` |
| Body Type | `Rigidbody2D` | `bodyType` |
| Font Size | `TextMeshProUGUI` | `fontSize` |

Выберите одно сравнение:

- `equals` — ожидаемое значение, в том числе `equals: ""` для пустой строки;
- `count` — целочисленная длина массива / списка (`ICollection`); `null` считается длиной 0.
  Само содержимое коллекции не сравнивается.

Сравнение `equals` зависит от типа прочитанного значения:

| Тип | Запись и сравнение |
| --- | --- |
| Число | `equals: 5` или `equals: 0.5`; абсолютная разница не больше допуска, по умолчанию `0.01`. |
| `bool` | `equals: true` / `false` (также допустимы те же слова, что у `optional`). |
| Enum | Имя, например `equals: "Kinematic"`, без учёта регистра и пробелов; допустимо целое числовое значение. |
| Строка | Точное совпадение с учётом регистра. |
| `Vector2/3/4`, `Vector2Int/3Int` | `equals: "0, 1, 0"`; можно указать только начальные координаты: `"0, 1"` у Vector3 сравнит x и y, оставив z свободной. Допустимы `;` вместо запятых и внешние круглые скобки. |
| `Color`, `Color32` | `equals: "#RRGGBB"` (альфа не сравнивается) или `"#RRGGBBAA"` (с альфой); допуск по каналам по умолчанию `0.02` в шкале 0–1. Также принимаются HTML-цвета Unity и 3–4 числа через запятую в шкале 0–1 (три числа задают альфу 1). |
| Ссылка на `UnityEngine.Object` | Точное имя объекта с учётом регистра; `none`, `null`, `пусто` или пустое значение означают отсутствие ссылки. |
| Другой тип | Точное совпадение с результатом `ToString()`. |

Необязательный `tolerance` — неотрицательный абсолютный допуск для чисел, координат вектора
и каналов цвета; на строки, enum, bool и `count` не влияет. При несовпадении прочитанного
значения подсказка — «сейчас X, в уроке Y»; для `count` — «сейчас элементов X, в уроке Y».
Если объект, компонент или член не найден, подсказка объясняет причину.

### Проверка урока и debug

`Tools -> AlgoNeoCourse -> Settings -> Validate Lessons` использует тот же `ParseRules`,
что и движок карточки: сообщает о неизвестных правилах, пустом блоке / обязательном значении,
недостающих параметрах `field`, неверных `optional`, `count`, `tolerance` и конфликтующих параметрах.
Проблемы `contains` выводятся как предупреждения, остальные ошибки разбора — как ошибки.
Это проверка формата: наличие объекта и фактические значения проверяются кнопкой в карточке.

По умолчанию ученик видит только карточку. Автор может включить исходник над карточкой:
`Tools -> AlgoNeoCourse -> Settings -> Open Validation Settings` → `Debug Show Check Source`
(по умолчанию выключено, с версии 1.9.0). Прежний неиспользуемый `Debug Render Check Blocks` удалён.
Галочки Validation Settings действуют сразу: слайд и меню `Docs` перестраиваются автоматически.

## 9. Окно курса

Окно открывается через:

```text
Tools -> AlgoNeoCourse -> Open Course Window
```

Горячие клавиши:

- `Left` / `Right`
- `R`
- `O`

Переход вперёд может блокироваться незавершённым квизом.

Навигация по слайдам — кнопками `<` / `>`, стрелками `Left` / `Right` и отметками заданий
на полосе прогресса. Слайд-ссылки (`unity://slide`) удалены в 1.6.0.

Полоса прогресса масштабирована по слайдам текущего урока: заливка доходит до самого дальнего
достигнутого слайда. Отметка «вы здесь» показывает текущий слайд; при возврате назад подпись
уточняет дальнюю точку, например «слайд 5/43 (дальше всего — 13)».
На слайде может быть по одной отметке квизов и практики; каждая объединяет задания своего типа.
Квизы отмечаются как «не пройден» / «пройден»: завершение с исчерпанными попытками тоже считается
прохождением для этой отметки. Практика имеет состояния «не выполнено», «выполнено»,
«засчитано с замечаниями», «не пройдена». Если проверок несколько, сначала учитывается провал,
затем незавершённость, затем замечания; иначе отметка выполнена.
Подсказка показывает тип задания, слайд и состояние. Нажатие переводит к соответствующему слайду,
но только в пределах уже пройденного: назад и вперёд до самого дальнего достигнутого слайда.
Дальше отметка не ведёт (подсказка: «сначала дойдите до этого слайда») — так нельзя перепрыгнуть
неотвеченный квиз.

## 10. Front matter

В начале урока можно использовать front matter:

```yaml
---
id: l2m2y3
module: 2
lesson: 3
title: Операторы и приоритет
tags: [beginner, csharp]
est_time_min: 15
---
```

Это необязательный блок, но он помогает держать единый формат.

## 11. Минимальный шаблон урока

````md
# Название урока

Короткое вступление.

---

## Теория

Объяснение и пример.

---

## Вопрос

```quiz
id: lesson-q1
kind: single
text: Вопрос по теме?
answers:
  - text: Верный ответ
    correct: true
  - text: Неверный ответ
```

---

## Пояснение

Почему ответ именно такой.

---

## Практика

```check
rules:
  - filename: "Example.cs"
  - contains: "Debug.Log"
```

---

## Итоги

- Что изучили
- Что закрепили
````

## 12. Ограничения

- не рассчитывайте на сложный HTML;
- таблицы — только pipe tables: без объединения ячеек и без таблиц внутри списков;
- подсветка синтаксиса в блоках кода есть для `csharp` / `cs` и `python` / `py`;
- не используйте неуникальные `id`;
- не полагайтесь на GIF как на воспроизводимое видео;
- `check` поддерживает только `object_exists`, `component_exists`, `field`, `scene_name`, `filename`, `contains`
  и описанные выше параметры, а не произвольный YAML; `contains` требует `filename`, `field` — имена членов C#;
- лучше не делать гигантские стены текста.

## 13. Чек-лист перед публикацией

- запись в `course1.json`, `course2.json` или `courseN.json` добавлена;
- путь `file` существует;
- слайды разделены `---`;
- у квизов уникальные `id`;
- медиа доступны;
- урок корректно открывается в `AlgoNeoCourse`.
